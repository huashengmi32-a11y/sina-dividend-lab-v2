# 需求确认单（Plan 模式）

> 项目：新浪财经历史分红数据获取与预处理（第三章作业）
> 仓库：`sina-dividend-lab-v2`　版本：v2.0　确认日期：2026-09-27
> 说明：本文档是启动实现前用 Plan 模式完成的确认结果。所有结论都已在后续
> 步骤中落地，可在仓库内逐条核对。

## 一、任务目标

把新浪财经个股页面上的历史分红信息，变成一份**可复核、可复现、可分析**的结构化数据集，
并把实现过程、数据结果、质量结论和网页测试一并交付。

三条主线：

1. **数据管线**：抓取原始页面 → 解析清洗 → 质量校验 → 导出多种格式；
2. **展示页面**：用一个页面讲清「抓了什么、怎么洗的、洗成什么样、质量如何」；
3. **质量保障**：用 Playwright 对页面做功能、布局与无障碍测试，并留档截图。

## 二、Plan 模式确认问答

| # | 待确认事项 | 确认结论 |
|---|-----------|---------|
| 1 | 数据源用哪个页面？ | 新浪财经「个股分红送转」列表页 + 每期「分红明细」页，两页口径都要采集，便于交叉校验 |
| 2 | 采多少只股票？ | 5 只，覆盖白酒（贵州茅台、五粮液）、家电（美的集团）、银行（招商银行）、保险（中国平安）四类行业，兼顾高派息与含配股两种形态 |
| 3 | 抓取范围到哪里？ | 每只股票的全部分红记录与配股记录，不设年份截断 |
| 4 | 抓取失败怎么办？ | 会话复用 + 0.8 秒限速 + 指数退避重试 3 次；原始 HTML 全量落地 `data/raw/`，解析失败不影响已抓数据 |
| 5 | 清洗到什么程度？ | 占位符统一为缺失、日期标准化为 `yyyy-mm-dd`、数值转浮点、派生 8 个分析字段 |
| 6 | 质量校验怎么做？ | 定义 10 条规则，覆盖完整性、方案有效性、日期顺序、数值范围、跨页一致性、主键唯一；问题分「错误 / 提示 / 信息」三级 |
| 7 | 源站脏数据怎么处理？ | 保留原始信息并打标；例如源站用 `1900-01-01` 表示未知公告日期时，记录保留但不参与年度派生与累计派息统计 |
| 8 | 输出哪些格式？ | CSV（中文表头，Excel 可直接打开）、JSON（英文字段名）、Excel 工作簿（多 Sheet 汇总）、质量报告 JSON |
| 9 | 展示页怎么做？ | 用 ui-ux-pro-max 技能生成设计系统，落地为单页静态站点，零网络依赖，`file://` 直接可看 |
| 10 | 测试怎么做？ | Playwright 覆盖功能、响应式布局、无障碍与截图留档；桌面与移动两个视口都要过 |
| 11 | 交付物有哪些？ | Git 仓库链接、展示页 + 截图、数据集、质量报告、测试报告、与 Agent 的完整对话记录（脱敏） |

## 三、字段口径（摘要）

完整字段字典见展示页「字段口径」一节与 `data/quality_report.json`。

| 类型 | 字段 | 口径 |
|------|------|------|
| 主键 | `stock_code` + `announce_date` | 派生 `record_id` 形如 `600519-2026-06-22#1` |
| 原始字段 | 公告日期、送股、转增、派息、方案进度、除权除息日、股权登记日、红股上市日 | 取自列表页 `sharebonus_1` 表 |
| 明细字段 | 税前红利、税后红利、股东大会决议公告日、红利到账日 | 取自明细页 `sharebonusdetail` 表 |
| 派生字段 | 分红年度、分配类型、实施年度、每股派息、是否含现金 / 送股 / 转增、公告日期存疑标记 | 由清洗脚本按固定规则生成 |

关键推断规则：公告月份不超过 8 月归入上一自然年度分配，9 月及以后归入本期中期分配；
该字段只用于分组统计，不代表公司官方口径，已在数据说明中显式标注。

## 五、验收标准

1. `python scripts/fetch_sina.py` 能在全新环境重新抓取全部页面，缓存命中时不重复请求；
2. `python scripts/preprocess.py` 能重复执行且输出稳定，控制台打印 10 条规则命中情况；
3. 展示页所有数字与 `data/` 下的产物一致，页面加载不发起任何外部请求；
4. `npx playwright test` 全绿：功能、布局、无障碍、截图四类用例全部通过；
5. 仓库中不包含任何账号、令牌、本机路径等敏感信息。

## 六、风险与对策

| 风险 | 对策 |
|------|------|
| 数据源页面改版导致解析失败 | 解析脚本先落盘再解析；规则校验会暴露字段缺失，便于快速定位 |
| 抓取过程被限流 | 0.8 秒请求间隔 + 重试退避 + 本地缓存，重复执行不再打扰数据源 |
| 源站存在脏数据 | 10 条质量规则 + 问题清单留痕，异常记录保留原值不静默丢弃 |
| 页面依赖外网资源导致离线打不开 | 字体自托管、数据内嵌为 `data.js`，测试中断言零外部请求 |
| 图文与数据不一致 | 展示页数字全部来自脚本产物，测试用产物反查页面数值 |

## 七、范围之外

- 不做行情、财务指标等分红以外的数据抓取；
- 不做登录态抓取或任何绕过访问控制的动作；
- 不做投资建议类分析，累计派息等指标仅用于课程演示。

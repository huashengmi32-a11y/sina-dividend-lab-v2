# BYD Market Lens Project Instructions

## 1. Project Background

- Product: a mobile-first, static H5 analysis page for BYD historical stock data.
- Audience: readers who need a compact, evidence-led review of BYD's 2023 daily
  adjusted-price history.
- Source data: `比亚迪后复权历史行情数据.xlsx`, sheet `Sheet2`, 242 trading rows.
- Coverage: 2023-01-03 through 2023-12-29. The source is historical and must not
  be presented as a live quote or current investment recommendation.
- Price field: all price analysis uses the supplied adjusted (`后复权`) OHLC data.
- Data schema: `日期, 开盘, 收盘, 最高, 最低, 成交量, 成交额, 振幅, 涨跌幅,
  涨跌额, 换手率`.
- The raw workbook is an input artifact. The committed runtime data is the
  normalized JSON generated by `scripts/prepare_data.py`.

## 2. Product and Technical Constraints

### Stack

- Build a static H5 page with Vue 3 and Vite.
- Use ECharts for the K-line, close-price, volume, and monthly-return charts.
- Use TDesign Mobile Vue for interactive controls. Do not hand-roll buttons,
  segmented selectors, switches, dialogs, tags, or navigation controls when a
  TDesign mobile component covers the requirement.
- Keep the built site fully static. `npm run build` must output to `docs/` so the
  page can be served by GitHub Pages without a backend.
- Use `base: './'` in Vite so the built page also works from a nested static host.
- Runtime data must be local. Do not fetch stock data from third-party APIs.

### Visualization

- Primary chart: accessible candlestick chart for daily adjusted OHLC data.
- Secondary view: close-price line or area view for trend reading.
- Add MA5, MA20, and MA60 overlays only when the MA switch is enabled.
- Volume is shown in a synchronized lower panel, not on a second unrelated page.
- Every chart value must also be available in the text/table fallback.
- Use ECharts canvas for the main chart, with a responsive resize observer.
- Keep the visible history to at most 252 trading days. The supplied data fits
  within this limit; do not add artificial downsampling that changes values.
- Avoid relying on color alone. Gains and losses must include a sign, arrow, or
  written label in addition to color.

### Skills and MCP

- Use the installed `ui-ux-pro-max` skill. Its persisted design system is
  `design-system/byd-market-lens/MASTER.md`.
- Run the UI/UX skill's design-system and focused searches before changing the
  visual hierarchy or interaction model.
- Use `tdesign-mcp-server` to look up the exact TDesign component APIs used by
  the page. Record the queried tools and component names in
  `deliverables/tdesign-mcp-usage.md`.
- Do not claim MCP usage without a reproducible command or script in the repo.

## 3. Visual Direction

- Mobile-first, app-like financial dashboard. Primary target: 390 x 844 CSS px.
- Support widths from 320 px to 1440 px without horizontal scrolling.
- Dark graphite base with warm amber accent, restrained red for gains, and teal
  for losses. This follows the Chinese A-share convention rather than the
  Western green-up/red-down convention.
- Use the UI/UX skill's dark OLED guidance as inspiration, but avoid a generic
  navy dashboard. Use semantic CSS tokens, not scattered raw colors.
- Typography: IBM Plex Sans for interface text, IBM Plex Mono for tabular
  figures. Chinese falls back to the local system sans-serif.
- Cards use a maximum 8 px border radius. Avoid nested cards and decorative
  floating sections.
- Use inline SVG icons from one consistent stroke family. Do not use emoji as
  structural icons.
- Motion is subtle and functional. Honor `prefers-reduced-motion: reduce`.

## 4. Data Analysis Rules

- Return: `(last close / first close - 1) * 100`.
- Maximum drawdown: compute from daily closing prices using running peaks.
- Annualized volatility: sample standard deviation of daily close-to-close
  returns multiplied by `sqrt(252) * 100`.
- Best and worst day: source `涨跌幅`, with the exact date shown.
- Monthly return: last close of month divided by previous month's last close
  minus one. The first month uses the first trading day's close as the base.
- Keep calculations reproducible in `scripts/prepare_data.py`.
- Describe observed history. Do not forecast prices, claim causality, or offer a
  buy/sell recommendation.

## 5. Accessibility and Interaction

- Normal text contrast must be at least 4.5:1; large text and UI boundaries at
  least 3:1.
- All interactive targets are at least 44 x 44 CSS px with visible focus rings.
- Controls must be keyboard reachable and have accessible names.
- Chart tooltips must not be the only way to obtain data. Include a recent
  trading table and textual summary.
- Respect safe-area insets on mobile.
- No layout shift when switching chart modes, MA visibility, or periods.
- No horizontal page overflow at 320, 375, 390, 768, 1024, or 1440 px.

## 6. Verification

Before delivery:

1. Run `npm run data`.
2. Run `npm run build`.
3. Run `npm run verify:mcp`.
4. Run the Playwright screenshot script at 390 x 844 and a wide viewport.
5. Check browser console errors, horizontal overflow, chart rendering, and
   interactive controls.
6. Verify the built page loads from a plain static server.
7. Commit source, generated `docs/` site, screenshots, and redacted conversation
   records. Never commit credentials, tokens, home-directory paths, or personal
   email addresses.
